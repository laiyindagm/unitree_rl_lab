## 3.3 混合内部优化

对于内部嵌入 $(\hat{v}_t, \hat{l}_t)$ 来说，最关键的是如何优化它以模拟机器人的响应，这种响应自然地嵌入在机器人的后继状态 $o^a_{t+1}$ 中。根据IMC原理，我们可以直接估计给定 $o^a_{t-H:t}$ 的 $o^a_{t+1}$。然而，由于机器人状态的高维度以及仿真与现实的差异，这具有挑战性。或者，考虑到我们在仿真环境中训练框架，我们可以直接学习使用其真实值来回归显式速度 $\hat{v}_t$。对于隐式响应 $\hat{l}_t$，我们提出将其建模到一个潜在空间 $\mathcal{Z} \subset \mathbb{R}^{16}$ 中，并通过对比学习优化使其接近后继状态。

在实践中，在每次迭代中，我们在每个环境中收集轨迹作为一个批次。如果一对 $o^a_{t+1}$ 和 $o^a_{t-H:t}$ 属于同一条轨迹，它们是正样本对；否则，它们是负样本对。这些样本对通过类似于SwAV（Caron等人，2020）的交换分配任务进行优化。给定从rollout轨迹中采样的一系列本体感知观测，我们可以从一次转移中推导出后续观测 $o^a_{t+1}$ 作为目标向量，并将拼接的历史观测 $o^a_{t-H:t}$ 视为源向量。我们确保增强在不同时间步之间保持一致。源向量和目标向量分别输入到源编码器和目标编码器中，以获得潜在特征 $l^{source}_t$ 和 $l^{target}_t$，这些特征通过L2归一化映射到高维空间中的单位球面上。为了从 $l^{source}_t$ 和 $l^{target}_t$ 预测聚类分配概率 $p^{source}_t$ 和 $p^{target}_t$，我们首先对原型应用L2归一化以获得归一化矩阵 $E = \{\bar{e}_1, ..., \bar{e}_K\}$，然后对源向量或目标向量与所有原型的点积取softmax：

$$
p^{source}_t = \frac{\exp\left(\frac{1}{\tau} {l^{source}_t}^\top e_k\right)}{\sum_{k'} \exp\left(\frac{1}{\tau} {l^{source}_t}^\top e_{k'}\right)}, \quad p^{target}_t = \frac{\exp\left(\frac{1}{\tau} {l^{target}_t}^\top e_k\right)}{\sum_{k'} \exp\left(\frac{1}{\tau} {l^{target}_t}^\top e_{k'}\right)}. \tag{1}
$$

这里，$p^{source}_t$ 和 $p^{target}_t$ 是历史观测 $o^a_{t-H:t}$ 映射到索引为 $k$ 的单个聚类的预测概率，而 $\tau$ 是温度参数。

为了获得上述预测概率的目标 $(q^{source}_1, ..., q^{source}_K)$ 和 $(q^{target}_1, ..., q^{target}_K)$，同时避免平凡解，我们对两个编码器应用Sinkhorn-Knopp算法（Cuturi，2013）。现在我们有了聚类分配预测和目标，表示学习的目标就是最大化预测准确率：

$$
J_{SwAV} = -\frac{1}{2H} \sum_{t=1}^{H} \left(q^{source}_t \log p^{target}_t + q^{target}_t \log p^{source}_t\right). \tag{2}
$$

**分析**。我们的方法可以最大化历史观测与下一观测之间潜在特征的相似性，隐式地建模外部状态，而不需要回归。这也通过利用批级信息（即不同类型地形中的不同环境属性）提高了运动策略的性能。我们对我们的方法和回归方法（Nahrendra等人，2023）的潜在输出进行了t-SNE（Van der Maaten & Hinton，2008）可视化。可视化显示，我们的混合内部模型对环境具有更可分离的编码，这意味着我们的方法携带了更精确的环境信息，从而具有更强的能力来识别机器人处于哪种地形上。

## 一、结论先行

**推荐方案**：在 HIMLoco 的 `HIMEstimator` 基础上，把它原本的 SwAV 自监督交换聚类损失，替换为**有监督对比学习 (SupCon, Khosla 2020)** + **可学习速度桶原型 (Prototypical Supervised Contrastive)** 的混合形式。

理由：
- 你的"标签"（速度桶）是**离散且已知**的，天然适合 SupCon 这一族「同标签为正、异标签为负」的损失，而 SwAV / PCL 这类无监督聚类是把"未知簇"硬贴到样本上，对你来说是绕了远路。
- 加一组**可学习的"桶原型"**（每个速度桶一个 prototype 向量）可以稳定优化，并且天然支持 in-batch 没有正样本时的 fallback；这与 HIM 当前 `self.proto = nn.Embedding(num_prototype, ...)` 的接口完全兼容，改动量最小。
- 历史观测建模上，把当前的 flatten-MLP 升级成 **1D TCN 或小型 Causal Transformer**，配合 **MoCo 式的 momentum target encoder + 队列**，可以解决 on-policy 训练时**单批次同桶样本太少**导致的对比信号弱的问题。

## 二、问题分析（与 HIM 原方法的差异）

HIM 原版的对比目标是「同一条轨迹中相邻时刻的潜变量相似」，**正负样本由"是否同 trajectory"定义**。代码体现在 `him_estimator.py` 的 `update`：

```python name=him_estimator.py url=https://github.com/InternRobotics/HIMLoco/blob/ef289acaa62795009363b7b819c9186690630441/rsl_rl/rsl_rl/modules/him_estimator.py#L77-L116
z_s = self.encoder(obs_history)        # 历史 → source latent
z_t = self.target(next_obs)            # 下一帧 → target latent
...
score_s = z_s @ self.proto.weight.T    # 32 个原型上的分配分数
q_s = sinkhorn(score_s); q_t = sinkhorn(score_t)
swap_loss = -0.5 * (q_s * log_p_t + q_t * log_p_s).mean()
estimation_loss = F.mse_loss(pred_vel, vel)
```

它隐式建模的是「环境响应」（地形等），因为 SwAV 的簇是**未对齐**的语义簇。你的需求不同：
- **正样本定义改成**：同一速度桶 `b(v_t)` 内的所有历史窗口；
- **负样本定义改成**：不同速度桶的历史窗口；
- **目标**：让潜空间显式按速度（步态）对齐。

这就从"无监督聚类对比"变成了"有监督类对比"。

## 四、编码器设计

### 4.1 输入与速度桶
- 输入：`obs_history ∈ R^{B × H × D_obs}`（HIMLoco 中 H≈10，D_obs 单步本体感）。
- 速度标签：取 `next_critic_obs` 中的 base-velocity `v_t ∈ R^3`（HIM 已经在用），或命令速度 `command_v`。建议**用命令速度而非真实速度作桶标签**——因为你想学的是「期望步态在不同目标速度下的差异」，不被扰动后真实速度的噪声污染。
- 分桶策略（举例，`v_x` 为主轴）：
  - 一维：把 `v_x ∈ [-1, 4] m/s` 等距 / 分位数划成 K=8~16 个桶；
  - 多维：对 `(v_x, v_y, ω_z)` 各自分桶后做笛卡尔乘积，或用 K-Means 在命令空间预聚类（K=16~32）。
  - **训练早期建议用粗桶（K=8），后期 curriculum 加细到 K=16~32**，避免冷启动时桶内样本太少。

### 4.2 网络结构（替换/扩展 `HIMEstimator.encoder`）

```
obs_history (B, H, D_obs)
   │
   ├── [option A] Flatten + MLP        ← 现状（最简单，可保留）
   ├── [option B] 1D TCN (3层 dilation 1/2/4, kernel=3)  ← 推荐
   └── [option C] Causal Transformer (2层, 4 heads, d=128) ← 如果 H≥20
   │
   ▼
backbone feature  f_t ∈ R^{128}
   │
   ├── velocity head:  pred_v = Linear(128 → 3)         ← 保留 HIM 的回归
   └── projection head: g(·) = Linear→GELU→Linear(→16) ← 对比用
                       z_t = L2_normalize(g(f_t))
```

要点：
1. **回归 head 与对比 head 解耦**（参考 SimCLR/SupCon 的 projector）：策略消费的是 `f_t` 或 `pred_v`，但对比损失只施加在 `z_t` 上，避免对比目标污染策略输入。
2. **L2 归一化 + 温度 τ** 是 SupCon 的关键，τ 推荐 0.07~0.2（HIM 现在 τ=3 偏大，因为它是 SwAV 设定）。
3. **桶原型**：`self.bucket_proto = nn.Embedding(K, 16)`，前向时也 L2 归一化。

### 4.3 (可选) Momentum Target Encoder + Queue

为缓解 on-policy 单 batch 内同桶正样本数少的问题：
- 维护 `encoder_momentum`，参数用 EMA 更新：`θ_m ← m·θ_m + (1-m)·θ`，m=0.99；
- 维护一个 FIFO 队列 `queue ∈ R^{Q × 16}` 存历史 z 与对应桶标签，Q=4096；
- 计算 SupCon 时把 queue 里相同桶的样本也算正样本。

## 五、训练范式与损失

### 5.1 Prototypical Supervised Contrastive Loss

设 batch 中样本 i 的桶标签 `y_i ∈ {1..K}`，潜变量 `z_i`，桶原型 `e_k`（已归一化）。

**主损失（桶原型 InfoNCE，必选）**：
$$
\mathcal{L}_{\text{proto}} = -\frac{1}{N}\sum_{i=1}^{N} \log \frac{\exp(z_i^\top e_{y_i}/\tau)}{\sum_{k=1}^{K}\exp(z_i^\top e_k/\tau)}
$$
作用：拉向自己桶的原型，推开其他桶原型。原型本身可学习，会自动散开。

**辅助损失（样本级 SupCon，可选但推荐）**：
$$
\mathcal{L}_{\text{supcon}} = \sum_{i}\frac{-1}{|P(i)|}\sum_{p\in P(i)} \log \frac{\exp(z_i^\top z_p/\tau)}{\sum_{a \neq i}\exp(z_i^\top z_a/\tau)}
$$
其中 P(i) = batch（+queue）中所有 `y=y_i` 的样本。利用 batch-level 信息，比单纯原型更细粒度。

**正则项（防原型坍缩）**：
$$
\mathcal{L}_{\text{div}} = \sum_{k\neq k'} \max(0,\ e_k^\top e_{k'} - m)^2,\quad m=0.3
$$
或者直接对原型做一次 Sinkhorn 正则（沿用 HIM 的代码）。

**总损失**：
$$
\mathcal{L} = \underbrace{\text{MSE}(\hat v, v)}_{\text{保留 HIM 速度回归}} + \lambda_1 \mathcal{L}_{\text{proto}} + \lambda_2 \mathcal{L}_{\text{supcon}} + \lambda_3 \mathcal{L}_{\text{div}}
$$
建议初值 `λ1=1.0, λ2=0.5, λ3=0.01, τ=0.1`。

### 5.2 Batch 构造（关键工程细节）

PPO/HIM 的 batch 是按 env × step 的，桶分布会严重不均。建议：
- 在 `compute_returns` 后、`update` 前，对 mini-batch 做**类平衡重采样**：每个 mini-batch 强制保证至少 `n_per_bucket≥4` 个样本来自每个出现的桶（配合 weighted sampler）。
- 或者用 **MoCo 队列**（5.3 节）来弥补。
- 训练 Isaac Gym 环境时，把 `commands` resample 频率适当提高，让 rollouts 内速度多样性更大。

### 5.3 数据增强（保持时间一致性，沿用 HIM 习惯）
- 对 `obs_history` 加高斯噪声（σ 与 sim-to-real noise model 一致）；
- 时间维 random crop / 时间窗口抖动；
- Joint dropout（随机置零 1~2 维），增强对传感器丢失的鲁棒性；
- ⚠️ 不要做会改变速度语义的增强（比如 IMU 旋转），否则破坏标签一致性。

## 六、最小改动落地：替换 `HIMEstimator.update` 的代码骨架

下面给一份**可直接套进 HIMLoco** 的伪代码，只改 `him_estimator.py`，对 `him_actor_critic.py` / runner 接口零改动。

```python name=him_estimator_supcon.py
import torch, torch.nn as nn, torch.nn.functional as F
from torch import optim

class HIMEstimatorSupCon(nn.Module):
    def __init__(self, temporal_steps, num_one_step_obs,
                 enc_hidden_dims=[128, 64, 16],
                 num_buckets=16, latent_dim=16,
                 temperature=0.1, lambda_proto=1.0, lambda_supcon=0.5,
                 lambda_div=0.01, learning_rate=1e-3, max_grad_norm=10.0,
                 use_momentum=True, momentum=0.99, queue_size=4096, **kwargs):
        super().__init__()
        self.H = temporal_steps
        self.D = num_one_step_obs
        self.K = num_buckets
        self.tau = temperature
        self.l1, self.l2, self.l3 = lambda_proto, lambda_supcon, lambda_div
        self.use_momentum = use_momentum
        self.m = momentum
        self.max_grad_norm = max_grad_norm

        # ---- encoder (TCN 推荐；这里用 MLP 演示，与原版接口一致) ----
        in_dim = self.H * self.D
        layers, d = [], in_dim
        for h in enc_hidden_dims[:-1]:
            layers += [nn.Linear(d, h), nn.ELU()]; d = h
        self.backbone = nn.Sequential(*layers)
        self.vel_head = nn.Linear(d, 3)                       # 显式速度
        self.proj_head = nn.Sequential(                       # 对比 head
            nn.Linear(d, d), nn.ELU(), nn.Linear(d, latent_dim))

        # 桶原型（替代 HIM 原 self.proto）
        self.bucket_proto = nn.Embedding(self.K, latent_dim)
        nn.init.normal_(self.bucket_proto.weight, std=0.02)

        # momentum encoder + queue (MoCo style)
        if use_momentum:
            self.backbone_m = nn.Sequential(*[nn.Linear(in_dim, enc_hidden_dims[0]), nn.ELU()] +
                [layer for h_prev, h in zip(enc_hidden_dims[:-2], enc_hidden_dims[1:-1])
                       for layer in (nn.Linear(h_prev, h), nn.ELU())])
            self.proj_head_m = nn.Sequential(
                nn.Linear(d, d), nn.ELU(), nn.Linear(d, latent_dim))
            for p in list(self.backbone_m.parameters()) + list(self.proj_head_m.parameters()):
                p.requires_grad = False
            self._copy_to_momentum()
            self.register_buffer("queue_z", F.normalize(torch.randn(queue_size, latent_dim), dim=-1))
            self.register_buffer("queue_y", -torch.ones(queue_size, dtype=torch.long))
            self.register_buffer("queue_ptr", torch.zeros(1, dtype=torch.long))
            self.queue_size = queue_size

        self.optimizer = optim.Adam(self.parameters(), lr=learning_rate)

    # -------- API 与原 HIMEstimator 保持一致 --------
    def encode(self, obs_history):
        f = self.backbone(obs_history.detach())
        vel = self.vel_head(f)
        z = F.normalize(self.proj_head(f), dim=-1)
        return vel, z

    def forward(self, obs_history):
        vel, z = self.encode(obs_history)
        return vel.detach(), z.detach()

    def get_latent(self, obs_history):
        return self.forward(obs_history)

    # -------- 速度桶函数（按 v_x 等距分桶；可换成多维 KMeans）--------
    @torch.no_grad()
    def velocity_to_bucket(self, v_cmd):  # v_cmd: (B,3)
        vx = v_cmd[:, 0].clamp(-1.0, 4.0)
        edges = torch.linspace(-1.0, 4.0, self.K + 1, device=vx.device)
        y = torch.bucketize(vx, edges) - 1
        return y.clamp(0, self.K - 1)

    # -------- 训练步 --------
    def update(self, obs_history, next_critic_obs, v_cmd=None, lr=None):
        if lr is not None:
            for g in self.optimizer.param_groups: g['lr'] = lr

        # 1) 速度回归 target & 桶标签
        v_true = next_critic_obs[:, self.D:self.D+3].detach()
        labels = self.velocity_to_bucket(v_cmd if v_cmd is not None else v_true)

        # 2) online encode
        f = self.backbone(obs_history)
        pred_v = self.vel_head(f)
        z = F.normalize(self.proj_head(f), dim=-1)        # (B, d)

        # 3) (可选) momentum encode for queue
        if self.use_momentum:
            with torch.no_grad():
                self._momentum_update()
                f_m = self.backbone_m(obs_history)
                z_m = F.normalize(self.proj_head_m(f_m), dim=-1)

        # 4) 原型损失：拉向本桶原型 / 推离他桶
        proto = F.normalize(self.bucket_proto.weight, dim=-1)   # (K, d)
        logits_p = z @ proto.T / self.tau                       # (B, K)
        loss_proto = F.cross_entropy(logits_p, labels)

        # 5) 样本级 SupCon（含 queue）
        if self.use_momentum:
            bank_z = torch.cat([z_m, self.queue_z], dim=0)
            bank_y = torch.cat([labels, self.queue_y], dim=0)
        else:
            bank_z, bank_y = z.detach(), labels
        loss_supcon = supcon_loss(z, labels, bank_z, bank_y, self.tau)

        # 6) 原型多样性正则
        sim = proto @ proto.T
        off = sim - torch.eye(self.K, device=sim.device)
        loss_div = F.relu(off - 0.3).pow(2).mean()

        # 7) HIM 速度回归
        loss_vel = F.mse_loss(pred_v, v_true)

        loss = loss_vel + self.l1 * loss_proto + self.l2 * loss_supcon + self.l3 * loss_div

        self.optimizer.zero_grad()
        loss.backward()
        nn.utils.clip_grad_norm_(self.parameters(), self.max_grad_norm)
        self.optimizer.step()

        if self.use_momentum:
            self._dequeue_and_enqueue(z_m.detach(), labels.detach())

        # 复用 HIM runner 期待的两个返回值
        return loss_vel.item(), (self.l1*loss_proto + self.l2*loss_supcon).item()

    # ---- helpers ----
    @torch.no_grad()
    def _copy_to_momentum(self):
        for pq, p in zip(self.backbone_m.parameters(), self.backbone.parameters()):
            pq.data.copy_(p.data)
        for pq, p in zip(self.proj_head_m.parameters(), self.proj_head.parameters()):
            pq.data.copy_(p.data)

    @torch.no_grad()
    def _momentum_update(self):
        for pq, p in zip(self.backbone_m.parameters(), self.backbone.parameters()):
            pq.data.mul_(self.m).add_(p.data, alpha=1 - self.m)
        for pq, p in zip(self.proj_head_m.parameters(), self.proj_head.parameters()):
            pq.data.mul_(self.m).add_(p.data, alpha=1 - self.m)

    @torch.no_grad()
    def _dequeue_and_enqueue(self, z, y):
        B = z.size(0); ptr = int(self.queue_ptr)
        end = ptr + B
        if end <= self.queue_size:
            self.queue_z[ptr:end] = z; self.queue_y[ptr:end] = y
        else:
            n1 = self.queue_size - ptr; n2 = B - n1
            self.queue_z[ptr:] = z[:n1]; self.queue_y[ptr:] = y[:n1]
            self.queue_z[:n2] = z[n1:]; self.queue_y[:n2] = y[n1:]
        self.queue_ptr[0] = end % self.queue_size


def supcon_loss(z, y, bank_z, bank_y, tau):
    """ Khosla et al., 2020. z:(B,d) anchors; bank:(N,d). """
    logits = z @ bank_z.T / tau                          # (B, N)
    logits = logits - logits.max(dim=1, keepdim=True).values.detach()
    pos_mask = (y.unsqueeze(1) == bank_y.unsqueeze(0)).float()
    # 排除自身（如果 bank 含 z 自身，要在调用方处理；这里假设 bank 是 momentum/queue）
    exp_logits = torch.exp(logits)
    log_prob = logits - torch.log(exp_logits.sum(dim=1, keepdim=True) + 1e-12)
    pos_count = pos_mask.sum(dim=1).clamp(min=1.0)
    loss = -(pos_mask * log_prob).sum(dim=1) / pos_count
    # batch 内某些样本本桶完全无正样本则跳过
    valid = (pos_mask.sum(dim=1) > 0).float()
    return (loss * valid).sum() / valid.sum().clamp(min=1.0)
```

接入 HIM 时唯一需要改的是 `him_on_policy_runner.py` 把 `command_v` 也透传给 `update` 即可（或在 `update` 内部从 `next_critic_obs` 切片获取）。

## 八、可能的进阶变体

- **Soft bucketing / Ordinal SupCon**：速度本质是连续量，硬分桶丢失邻近性。可以把正样本权重设成 `w_ij = exp(-|y_i - y_j|² / σ²)` 的软标签形式（参考 *Rank-N-Contrast*, NeurIPS 2023），既保留有序结构又仍是有监督对比。
- **Multi-positive InfoNCE with hierarchical buckets**：粗桶（前进/后退/横移）+ 细桶（速度大小），分两层对比，效果更稳定。
- **结合时间一致性（HIM 原项）**：保留"同 trajectory 相邻帧"作为额外正样本，与"同速度桶"取并集，这样既建模环境响应又建模速度步态。这其实就是把 HIM 与 SupCon 融合，实测通常优于单一目标。

## 1. 用 cmd 作为标签的潜在问题与建议

你担心是对的，但**结论是仍然推荐用 cmd 作为主标签**，只是要做一些处理来应对 "cmd ≠ actual" 的早期偏差。

### 1.1 用 cmd 作标签的理由（为什么仍然推荐）
- **你想学的是"步态调度"，不是"测速器"**：步态/相位/支撑模式是由策略**为了去追踪 cmd**而主动选择的内部决策。换句话说，相同 cmd 下哪怕实际速度还没追上，策略内部的姿态/相位/抬腿高度也应该是一类——这恰好是你想让 latent 对齐的东西。HIM 把"显式速度回归"独立出来正是这个思路：**显式头去逼近真实 v，对比头去对齐"语义意图"**。
- **cmd 标签无噪声、稳定、离散**，正好契合 SupCon 对"标签"的要求；而 actual_v 是带噪、连续、还会被扰动/地形改变的，作为离散桶 label 会出现"同一段平稳行走前后帧分到不同桶"的标签抖动，反而把对比信号打散。
- **样本平衡可控**：用 cmd 做标签，你能在 env reset 时主动 resample cmd 来保证桶均衡；用 actual_v 标签则桶分布完全由策略当前能力决定，前期会严重偏向 0~低速桶，导致高速桶几乎没正样本，对比损失退化。

### 1.2 但 cmd 与 actual 偏差大确实会带来两类问题

**问题 A：早期"跟不上"导致同一桶内的轨迹方差极大**
比如 cmd_vx=2.0 的桶里，前期 actual 可能在 0.3~1.5 之间；这个桶的"语义"是混的——既有"原地踏步"又有"勉强前进"。SupCon 会强行把这堆全拉到一个簇，反而损害表征。

**问题 B：cmd 与执行解耦，latent 学到的是"目标",不是"已发生的动力学"**
如果你下游想用 latent 做 "状态识别 / 残差控制 / sim2real shift detection"，cmd-based latent 是不够的。

### 1.3 实操建议（折中方案，按推荐度排序）

**(a) Curriculum on label source（强烈推荐）**
- 训练前 ~30% iter：标签使用 `clip(cmd, 0, achievable_range)` 或直接用 cmd——此时只是为了让 latent 大致按"意图"分簇；
- 训练中后期：标签切换为 **EMA 平滑的 actual velocity 分桶**，或 `0.5*cmd + 0.5*actual_smoothed`。

**(b) Gating: 只在 cmd≈actual 的样本上算对比损失（推荐）**
```python
mask = (torch.norm(v_cmd - v_actual_smoothed, dim=-1) < tol)  # tol=0.3 m/s
loss_supcon = (loss_supcon_per_sample * mask).sum() / mask.sum().clamp_min(1)
```
回归头照常算（它需要全样本），对比头只在"指令已被有效跟踪"的样本上算。这样桶内语义干净。

**(c) Soft label / Ordinal SupCon（最稳，推荐配合 a 用）**
不要硬分桶，使用基于"标签之间的距离"的软正样本权重：
$$w_{ij} = \exp\!\left(-\frac{\|y_i - y_j\|^2}{\sigma^2}\right)$$
其中 $y$ 既可以是 cmd 也可以是 actual。即使 actual 抖动，相邻桶之间也会有平滑的吸引力，不会出现"差 0.01 m/s 就完全是负样本"的硬切。参考 *Rank-N-Contrast* (NeurIPS 2023)。

**(d) 把 cmd 也作为输入特征**
`obs_history` 通常已经包含 cmd，所以 encoder 实际上**能同时看到 cmd 和 actual**，让它自己学会区分"cmd 与 actual 一致 vs 偏离"。这点是天然的，不用额外改。

**最终推荐组合：cmd 作为主标签 + (b) gating + (c) ordinal/soft 权重**。这样训练前期对比信号弱但不错（桶里只有真正在执行的样本），后期变密集且语义清晰。

## 2. Causal Transformer 简介与编码用法

### 2.1 什么是 Causal Transformer
"Causal" = **因果遮罩 (causal mask)**：在 self-attention 的注意力矩阵上加一个上三角 −∞ 的 mask，使时刻 t 只能 attend 到 ≤ t 的时刻。它就是 GPT 类语言模型用的解码器架构，用在时序信号上等价于一个"可学习的、变长感受野的时间编码器"。

它和别的时序编码器对比：
| | 感受野 | 长程依赖 | 推理速度 | 是否有时间不对称性 |
|---|---|---|---|---|
| MLP(flatten) | 固定=H | 弱（无归纳偏置） | 最快 | 否 |
| 1D TCN | 固定=∑dilation | 中（要堆层） | 快 | 是（causal conv） |
| LSTM/GRU | ∞（理论） | 中（梯度衰减） | 快但串行 | 是 |
| **Causal Transformer** | ∞（窗口内） | **强** | 中（O(H²)） | 是 |

对你 H=10~30 的本体感历史，**H 较短时 Causal Transformer 没必要，TCN 性价比更高**；如果你打算把 H 拉长到 50~100（比如要捕捉长周期步态、地形扰动恢复），Causal Transformer 优势明显。

### 2.2 用于编码 obs_history 的最小结构

```python name=causal_transformer_encoder.py
class CausalTransformerEncoder(nn.Module):
    def __init__(self, d_obs, d_model=128, n_heads=4, n_layers=2,
                 max_len=50, dropout=0.0):
        super().__init__()
        self.in_proj = nn.Linear(d_obs, d_model)
        self.pos = nn.Parameter(torch.zeros(1, max_len, d_model))  # 学习式位置编码
        layer = nn.TransformerEncoderLayer(
            d_model, n_heads, dim_feedforward=4*d_model,
            dropout=dropout, activation='gelu', batch_first=True, norm_first=True)
        self.blocks = nn.TransformerEncoder(layer, num_layers=n_layers)
        self.norm = nn.LayerNorm(d_model)

    def forward(self, x):                  # x: (B, H, d_obs)
        B, H, _ = x.shape
        h = self.in_proj(x) + self.pos[:, :H]
        # causal mask: H×H 上三角 -inf
        mask = torch.triu(torch.full((H, H), float('-inf'),
                                     device=x.device), diagonal=1)
        h = self.blocks(h, mask=mask)      # (B, H, d_model)
        h = self.norm(h)
        # 用最后一个时刻 token 作为整段历史的总结（类似 GPT 的 last-token pooling）
        return h[:, -1]                    # (B, d_model)
```

要点：
- **最后时刻 token 作为序列摘要**：因为 causal mask 下只有 t=H-1 这个 token 看到了全部历史。
- **`norm_first=True` (Pre-LN)** 在小模型/RL 场景更稳。
- **位置编码用可学习的就够了**，序列短不需要 RoPE/ALiBi。
- 输出 `f` 之后接你的 `vel_head` 和 `proj_head`，与 MLP/TCN 版本完全可插拔。

### 2.3 在 RL 推理时的成本
- 一次 forward 是 O(H²·d)，H=20、d=128 时大约 ~50K MAC，**完全可以实时**（4~10 μs 量级），机器人控制频率 50 Hz 没压力。
- 部署到 onnx / TensorRT 时建议把 H 固定（比如固定 H=20），就是个完全静态图。

### 2.4 什么时候选它
- H ≥ 30；
- 你想用同一个 encoder 兼顾"短窗预测下一帧"和"长窗识别步态/地形"（多任务）；
- 想用预训练 / 跨 robot transfer：transformer 比 MLP 更利于 fine-tune。

否则，**TCN 是更务实的默认选择**（参数少、推理快、归纳偏置好）。

## 3. (v_x, v_y, ω_z) 笛卡尔乘积分桶的细节

### 3.1 直接乘积的问题
假设各自分 K=8 桶，乘积就是 8³=512 桶。问题：
- **大部分组合是空的或极少**（你不会下 v_x=−1 同时 ω_z=2 这种命令）；
- **桶内样本数极不平衡**，SupCon 退化为"少数桶有正样本，多数没有"。

### 3.2 推荐的几种做法（按从简到繁）

**做法 A：分维度独立对比，再相加（推荐起步）**
不做笛卡尔积，分别给 `v_x, v_y, ω_z` 各分 K_x, K_y, K_ω 桶，每个维度训练一组独立的桶原型与 SupCon：
$$\mathcal{L} = \mathcal{L}^{(v_x)}_{\text{proto}} + \mathcal{L}^{(v_y)}_{\text{proto}} + \mathcal{L}^{(\omega_z)}_{\text{proto}}$$
- 一个 latent，多个分类头；
- 桶数线性增长 (K_x+K_y+K_ω) 而非乘积；
- **要求 latent 同时编码三个语义维度**——这其实更符合"步态由三轴速度决定"的直觉。

**做法 B：在 cmd 空间预聚类（KMeans / 手工划分）**
对所有可能的 cmd 在 R³ 中跑 KMeans(K=16~32)，得到 K 个有意义的"行为模式"（前进、后退、左转前进、原地转、横移…）。**优点**：桶语义清晰、样本均衡；**缺点**：依赖你 cmd 采样分布，训练前要先 cache 一批 cmd 跑聚类。

**做法 C：层次桶 (Hierarchical SupCon)**
两层标签：
- 粗标签：`{stand, pure_wz, forward, backward, lateral, mixed}` ←—— 正好契合你 hard constraint 里的 3-way mode isolation！
- 细标签：在每个粗类里再按速度大小分 4~8 桶。

损失：
$$\mathcal{L} = \alpha \mathcal{L}_{\text{coarse}} + \beta \mathcal{L}_{\text{fine}}$$
粗类信号强、保证大簇分开；细类信号微调簇内结构。这跟你"3-way mode isolation"的硬约束是天然对齐的，**强烈建议你用 C**。

**做法 D：Soft / Ordinal**（接 1.3.c）
直接用 cmd 向量的欧氏距离（或加权距离 `diag(w_x,w_y,w_ω)`）做正样本相似度的连续权重，完全跳过分桶。

### 3.3 给你的具体推荐
结合你的项目约束（"keep at least 3-way mode isolation `{standing, pure_wz, other}`"），**做法 C 几乎是为你的约束量身定做的**：

```python
def cmd_to_coarse_bucket(cmd):     # cmd: (B, 3) = (vx, vy, wz)
    vx, vy, wz = cmd.unbind(-1)
    standing = (vx.abs()<0.05)&(vy.abs()<0.05)&(wz.abs()<0.05)
    pure_wz  = (vx.abs()<0.05)&(vy.abs()<0.05)&(wz.abs()>=0.05)
    other    = ~(standing | pure_wz)
    return standing.long()*0 + pure_wz.long()*1 + other.long()*2

def cmd_to_fine_bucket(cmd, coarse, K_fine=8):
    # 在 'other' 类里按 |v_xy| 大小再分 K_fine 桶；前两类各占 1 桶
    speed = cmd[:, :2].norm(dim=-1)
    fine = torch.bucketize(speed, torch.linspace(0, 2.0, K_fine+1, device=cmd.device)) - 1
    fine = fine.clamp(0, K_fine-1)
    # 全局编号: standing=0, pure_wz=1, other_k = 2..2+K_fine-1
    out = torch.where(coarse==0, torch.zeros_like(fine),
          torch.where(coarse==1, torch.ones_like(fine),
                                  fine + 2))
    return out
```

这样总桶数 = 2 + K_fine，可控且语义清晰，并且**对比损失天然在执行你的 3-way mode isolation 硬约束**。

## 4. 关于 HIM 的 source/target encoder & 你的"语义不一致"质疑

### 4.1 HIM 是怎么做的？两个**形状不同**的输入用的是**两个不同的 encoder**

看代码就一清二楚：

```python name=him_estimator.py url=https://github.com/InternRobotics/HIMLoco/blob/ef289acaa62795009363b7b819c9186690630441/rsl_rl/rsl_rl/modules/him_estimator.py#L36-L51
# Encoder：吃 H × D_obs 的历史，输出 (vel_3 + latent_16)
enc_input_dim = self.temporal_steps * self.num_one_step_obs
enc_layers = []
for l in range(len(enc_hidden_dims) - 1):
    enc_layers += [nn.Linear(enc_input_dim, enc_hidden_dims[l]), activation]
    enc_input_dim = enc_hidden_dims[l]
enc_layers += [nn.Linear(enc_input_dim, enc_hidden_dims[-1] + 3)]
self.encoder = nn.Sequential(*enc_layers)

# Target：吃 1 × D_obs 的下一帧，输出 latent_16
tar_input_dim = self.num_one_step_obs
tar_layers = []
for l in range(len(tar_hidden_dims)):
    tar_layers += [nn.Linear(tar_input_dim, tar_hidden_dims[l]), activation]
    tar_input_dim = tar_hidden_dims[l]
tar_layers += [nn.Linear(tar_input_dim, enc_hidden_dims[-1])]
self.target = nn.Sequential(*tar_layers)
```

并且 `target` encoder 不是 momentum 也不是 stop-grad，而是**和 encoder 一起被同一个 optimizer 训练**。两个网络的输出落到**共享的原型空间**，靠 SwAV 的 swapped assignment 把两侧拉到一致。

所以 HIM 的设计实际上是：
- 两个独立 encoder（异构输入，异构架构）；
- 共享 prototype；
- 用 SwAV 做"潜空间一致性"的对齐目标。

### 4.2 你的质疑非常对："语义不一致"会破坏对比

**两类正样本的语义确实不同**：
- HIM 原版正样本（"历史 → 下一帧"）：**语义是"动力学/响应一致性"**——下一帧承载了对历史的真实响应。
- 你的新正样本（"同速度桶的两条历史"）：**语义是"任务模式一致性"**——表达"我正在执行同一类步态"。

如果硬塞到**同一个 latent space, 同一个 InfoNCE 分母**里，会出现：同桶但响应差异大（例如一个在平地 trot，一个在斜坡 trot）的两条历史被强行拉近，反而让 latent 既不能精准表示"动力学响应"也不能精准表示"模式"——这就是你说的"扩充不好"。

### 4.3 推荐方案：**多目标 / 多头（multi-task contrastive head）**

不要把两类正样本合并到一个损失里，而是**用同一个 backbone + 两个独立的 projection head + 两个独立的 prototype 集**：

```
                 ┌─► proj_head_dyn  ─► z_dyn ─┐  与 target encoder 的 z_t 做 InfoNCE
obs_history ─► backbone f                      │  （HIM 原始的"动力学响应一致性"）
                 └─► proj_head_mode ─► z_mode ─┘  与 bucket prototypes 做 SupCon
                                                  （你的"速度桶模式一致性"）
next_obs   ─► target_encoder ─► z_t  （只配对 z_dyn）
```

总损失：
$$\mathcal{L} = \mathcal{L}_{\text{vel-MSE}} + \lambda_{\text{dyn}} \mathcal{L}_{\text{dyn-contrast}}(z_{\text{dyn}}, z_t) + \lambda_{\text{mode}} \mathcal{L}_{\text{supcon}}(z_{\text{mode}}, y)$$

下游策略用 `actor_input = [obs_t, pred_v, z_dyn, z_mode]`（或者只用 `concat(z_dyn, z_mode)`），让策略自己决定怎么融合。

**这样做的好处**：
1. **语义解耦**：z_dyn 学动力学响应（继承 HIM 优势，对地形/扰动建模），z_mode 学步态模式（你的目标），互不污染；
2. **梯度互相不抢**：两组原型独立，温度可以独立调；
3. **可消融**：你能分别 lesion 每一头，验证它们各自的贡献；
4. **与你的 3-way mode isolation 约束高度契合**：z_mode 的 supcon 直接由 coarse bucket 监督，约束会非常显式地落到 latent 几何上。

### 4.4 如果你坚持只想要单 head（更简洁但需要小心）

可以把"同 trajectory 相邻"作为**软正样本**而不是硬正样本，例如把 SupCon 的正样本掩码改成：
```
M_ij = 1.0  if y_i == y_j         (同桶，强正)
     = α    if 同 trajectory 邻近  (弱正, α=0.3)
     = 0    otherwise
```
但这种调权超参敏感，不如双头干净。

你这个问题问到了根上——这是 **representation 与 policy gradient 之间的"耦合断点"**。我先把这个断点形式化，再给可行方案族，最后落到最推荐的具体配方。

---

## 一、先把"断点"说清楚

把你目前的设计写成数据流：

```
obs_history ──► encoder ──► z (gait latent)
                              │
                              ▼
        actor(obs, cmd, z) ──► a ──► env ──► r_track
```

PPO 的策略梯度是 `∇θ log π(a|s) · A(s,a)`。注意：**z 只是 actor 的输入**，它是否"按速度桶分簇"完全由 encoder 的辅助 loss 决定，**actor 的梯度并不会要求 π 在不同 z 下产生不同的 a**——因为只要 r_track 一样，π 完全可以"忽略 z"或"对所有 z 输出同一种步态"。

形式化地说：你需要让损失中出现**显式依赖 (cmd, π) 之间互信息的项**，policy gradient 才会有"为不同 cmd 长出不同行为"的方向分量。一句话：

> **要让步态分化，就要把"行为可分性"本身做成 reward 的一部分，而不是只做成 representation 的一部分。**

这正是 Skill Discovery 文献（DIAYN、DADS、CIC、BeCL、METRA、SMERL…）的核心。区别只在于：他们的"skill" $z$ 是**采样的**，而你的"skill"是**外部给定的离散 cmd 桶**——这其实让问题更简单。

---

## 二、可用方法族（按"梯度怎么回传到 π"分类）

### 类别 A：判别器式内在奖励（DIAYN-conditioned）
训练判别器 $q_\phi(b \mid \tau)$ 从一段短轨迹 $\tau = (s_{t-H..t}, a_{t-H..t})$ 预测速度桶 $b$，把它的对数似然作为 PPO 的额外 reward：

$$r^{\text{int}}_t = \log q_\phi(b_t \mid \tau_t) - \log p(b_t)$$

- **梯度怎么回传**：$r^{\text{int}}$ 进入 advantage，PPO 的 policy gradient 自然驱动 π 去**让自己的 rollout 更"可被识别为桶 b"**——不同桶就被迫产生不同行为。
- **判别器侧**：用 cross-entropy 监督训练，`detach(τ)`，不让梯度污染 π。
- **直觉**：把"我现在走的步态属不属于桶 b"变成可微的 reward。
- 完全无需任何步态先验、demo、clock、duty-factor 奖励。

### 类别 B：动力学判别（DADS-conditioned）
不是从 $\tau$ 判别 $b$，而是判别 **next-state 给定 (s, b)**：
$$r^{\text{int}}_t = \log \frac{q_\phi(s_{t+1}\mid s_t,b)}{\sum_{b'} q_\phi(s_{t+1}\mid s_t,b')}$$

- **优点**：直接对 transition 而非整段轨迹建模，对地形扰动鲁棒；"步态差异"=="转移分布差异"非常自然。
- **缺点**：要建一个生成式 next-state model，比类别 A 复杂。

### 类别 C：对比式内在奖励（CIC-conditioned / BeCL）
用 InfoNCE 估计 $I(\tau; b)$，把估计值作为 reward：

$$r^{\text{int}}_t = \log \frac{\exp(f(\tau_t)^\top g(b_t)/\tau)}{\sum_{b'}\exp(f(\tau_t)^\top g(b')/\tau)}$$

- 这与你**已经在做的对比 encoder 完美耦合**：你之前讨论的 `z_mode` 就是 $f(\tau_t)$，桶原型就是 $g(b)$。把"对比 logit"既当 representation loss、又当 reward——一份网络两份用。
- **比 DIAYN 更稳**：CIC 论文证明 InfoNCE 比直接训练分类器在大 skill 数下方差更小。

### 类别 D：动作分布的条件互信息（轻量但弱）
在 state 几乎相同时，奖励"不同 cmd 下 π 的动作分布尽量不同"：
$$r^{\text{int}} \propto -\sum_{b'\neq b} \mathrm{sim}\big(\pi(\cdot|s,b),\, \pi(\cdot|s,b')\big)$$

- 实现简单：每步对 actor 多前向几次（不同 cmd），算 action distribution 之间的 KL/cosine。
- **缺点**：信号弱，并且鼓励"动作向量数值不同"未必 == "步态不同"（步态是相位/接触模式层面的统计量）。

### 类别 E：SMERL 门控（不是新方法，是关键 trick）
上面所有方法都有共同风险：内在奖励太强 → 策略放弃跟踪 cmd 去"博取可分性"。SMERL 的解法很简洁：

$$r_t = r^{\text{ext}}_t + \alpha \cdot \mathbb{1}\big[\bar r^{\text{ext}} > \beta\big] \cdot r^{\text{int}}_t$$

只有当近期跟踪 reward 已达到阈值时才发放内在奖励——**先学会跟得上，再去分化步态**。这对你的情形（早期 cmd≈actual 偏差大）尤其关键。

### 类别 F：Lipschitz / METRA 类（不太适合你）
METRA、LSD 是为"无 cmd"的纯 unsupervised skill discovery 设计的，目标是让 latent 在 metric space 中线性铺开。你 cmd 已给定且离散，这类方法的优势用不上。**不推荐**。

| 方法 | 是否给 π 梯度 | 与你现有对比 encoder 的复用度 | 实现复杂度 | 对 cmd-actual 偏差鲁棒性 | 推荐度 |
|---|---|---|---|---|---|
| A. DIAYN-conditioned | ✅ 强 | 中（额外 classifier） | 低 | 中 | ⭐⭐⭐⭐ |
| B. DADS-conditioned | ✅ 强 | 低（要 generative model） | 高 | 高 | ⭐⭐⭐ |

## 四、推荐配方的具体落地

### 4.1 数学定义

记你已有的：
- `z_mode_t = f(obs_history_t)`，单位球面上；
- `e_b`，桶原型，单位球面上；
- $b_t$ = 当前 cmd 的桶。

**Representation loss（你之前已经设计的，照旧）**：
$$\mathcal{L}_{\text{proto}} = -\log \frac{\exp(z_{\text{mode},t}^\top e_{b_t}/\tau)}{\sum_{b'} \exp(z_{\text{mode},t}^\top e_{b'}/\tau)}$$

**内在奖励（关键的新东西）**：
$$\boxed{\,r^{\text{int}}_t = \underbrace{\log \frac{\exp(z_{\text{mode},t}^\top e_{b_t}/\tau)}{\sum_{b'} \exp(z_{\text{mode},t}^\top e_{b'}/\tau)}}_{=-\mathcal{L}_{\text{proto}}\text{ 的样本值}} + \log K\,}$$

加 $\log K$ 是为了把内在 reward 居中到 0 附近（均匀分配下 reward=0）。注意这个 reward 是 **detach 掉 encoder 梯度** 的——它纯粹用作标量 reward 喂给 PPO；而 encoder 仍然由 $\mathcal{L}_{\text{proto}}$ 通过普通监督学习更新。

**SMERL 门控**：
$$r_t = r^{\text{track}}_t + \sum_j w_j r^{\text{aux},j}_t + \alpha \cdot \mathrm{gate}_t \cdot r^{\text{int}}_t$$

$$\mathrm{gate}_t = \sigma\!\left(\kappa \cdot (\bar r^{\text{track}}_{[t-T:t]} - \beta)\right)$$

用 sigmoid 而非 hard 阈值，避免 reward 阶跃。$\beta$ 取你跟踪 reward 在"勉强能跟上"水平的值；$\alpha$ 从小到大 schedule（例如 0 → 0.1）。

### 4.2 为什么这样能产生"步态分化"梯度（直觉证明）

PPO 对 actor 的更新方向中会出现：

$$\nabla_\theta \mathbb{E}_{\pi_\theta}\!\left[\sum_t \gamma^t \alpha\cdot\mathrm{gate}_t \cdot r^{\text{int}}_t\right]$$

$r^{\text{int}}_t$ 高 ↔ encoder 输出的 $z_{\text{mode},t}$ 接近本桶原型 $e_{b_t}$、远离他桶原型。但 $z_{\text{mode},t}$ 是 obs_history 的函数，而 obs_history 是**策略历史动作的果**。所以策略要拿到这个 reward，**必须改变自己的动作序列**让产生的 obs_history 更"像本桶、不像他桶"。当 $\mathcal{L}_{\text{proto}}$ 收敛、各桶原型在 latent 空间张开后，"更像本桶"在 obs 空间上对应的就是步态级的统计差异（接触相位、足端轨迹周期…）——而**这一切完全没有人工先验介入**。

### 4.3 在 `unitree_rl_lab` 里的接入点

不需要改 IsaacLab MDP 本身，只需要：

1. **新增一个 `ContrastiveIntrinsicReward` 模块**，挂在 `manager_based_rl_env` 的 `reward_manager` 下：
   - 输入：`obs_history`（已存在的 history buffer）、`command_buf`；
   - 内部：调用你训好/在训的 `z_mode = encoder(obs_history)` 与 `proto`；
   - 输出：标量 reward。
2. **门控**：维护一个 EMA 跟踪 `r_track`，`gate = sigmoid(κ(EMA - β))`。
3. **Schedule**：`α(it) = α_max · min(1, it / warmup)`，`warmup` 可以设到 PPO 总 iter 的 30%。
4. **Encoder/proto 训练**：仍然在 PPO update 阶段做（与 HIM 相同位置），与 PPO 同一个 batch；记得 reward 计算时用 **encoder 的 detach 输出**，避免 PPO 通过 reward 反传到 encoder（那会导致 reward hacking）。

伪代码骨架：

```python name=intrinsic_reward.py
class CICIntrinsicReward(nn.Module):
    def __init__(self, encoder, proto, tau=0.1, K=10):
        super().__init__()
        self.encoder, self.proto, self.tau, self.K = encoder, proto, tau, K
        self.register_buffer("track_ema", torch.tensor(0.0))
        self.ema_m = 0.99

    @torch.no_grad()
    def compute(self, obs_history, cmd_bucket, r_track,
                alpha, beta, kappa=10.0):
        z = F.normalize(self.encoder(obs_history)[1], dim=-1)   # (B, d)
        e = F.normalize(self.proto.weight, dim=-1)              # (K, d)
        logits = z @ e.T / self.tau
        log_p = F.log_softmax(logits, dim=-1)
        r_int = log_p.gather(1, cmd_bucket.unsqueeze(1)).squeeze(1) + math.log(self.K)

        self.track_ema.mul_(self.ema_m).add_(r_track.mean(), alpha=1 - self.ema_m)
        gate = torch.sigmoid(kappa * (self.track_ema - beta))
        return alpha * gate * r_int          # 直接累加到 step reward
```

|---|---|---|
| **Reward hacking**：策略放弃跟踪去博取 r_int | 跟踪 reward 跌、桶可分性飙升 | SMERL 门控 + α 上限 + α warmup |

# 算法设计文档：基于条件对比内在奖励的步态自演化机制

**Conditional Contrastive Intrinsic Reward for Emergent Gait Differentiation (CCIR-GD)**

---

## 1. 背景与动机

### 1.1 问题陈述
在基于强化学习的足式机器人运动控制中，传统方法依赖**步态先验奖励**（duty factor、swing height、clock signal、参考运动等）来诱导机器人在不同速度下使用不同步态。这类先验：
- 引入人工偏置，限制策略发现新步态的可能性；
- 跨机器人 / 跨任务迁移性差；
- 调参负担重，奖励之间容易互相冲突。

我们希望去掉所有步态形态先验，仅给定离散速度指令（cmd），让策略**自发地**在不同速度桶中演化出不同的步态。

### 1.2 现有方案的局限
- **纯跟踪奖励**：策略可以用一种"通用步态"覆盖所有速度，没有动力分化。
- **对比表征学习（仅作 encoder 输入）**：能让 latent 按速度桶分簇，但梯度只更新 encoder，不直接更新策略；策略"知道自己在做什么"，却**没有动力去改变**。
- **DIAYN/DADS 等 skill discovery**：原本面向无监督潜变量 z 而非外部给定 cmd，需要适配。

### 1.3 核心洞见
> **要让步态分化真正发生，必须把"行为可分性"本身做成 reward，而不是只做成 representation。**

策略梯度只对出现在 reward / advantage 中的目标敏感。把"在不同 cmd 下产生可被区分的轨迹"显式地编入奖励，PPO 的更新方向中才会出现"为不同 cmd 长出不同行为"的分量。

---

## 2. 设计目标

### 2.1 功能目标
1. **F1**：在不引入任何步态形态先验（无 clock、duty factor、swing height、足端轨迹模板、参考动作）的前提下，策略在不同速度桶中演化出可观测的步态差异。
2. **F2**：保留并不损害原有的速度跟踪性能与安全性约束。
3. **F3**：模块可插拔，与现有 PPO + manager-based RL env 框架兼容。

### 2.2 非功能目标
1. **N1**（无 reward hacking）：策略不能通过"欺骗判别器"而牺牲跟踪能力来获取内在奖励。
2. **N2**（训练稳定）：内在奖励的引入不应显著增大训练方差或导致早期发散。
3. **N3**（可解释 / 可消融）：能独立评估"表征学习"与"内在奖励"两部分的贡献。
4. **N4**（计算开销可控）：每步推理与训练开销相对原始 PPO 增加 ≤ 15%。

### 2.3 非目标（明确不做的事）
- 不试图发现"新颖的"无监督 skill；cmd 桶是预先给定的。
- 不引入任何参考运动 / 模仿学习信号。
- 不修改 PPO 算法本体。

---

## 3. 算法设计思路

### 3.1 总体框架
本算法由三个相互耦合但职责分离的组件构成：

```
                    ┌────────────────────────────────────────────┐
                    │               obs_history                   │
                    └──────────────────┬──────────────────────────┘
                                       │
                              ┌────────▼────────┐
                              │   Encoder f(·)  │
                              │   (shared)      │
                              └────┬───────┬────┘
                                   │       │
                       ┌───────────┘       └───────────┐
                       ▼                               ▼
                  z_dyn (HIM 原)                  z_mode (新)
                       │                               │
                       │                    ┌──────────┴──────────┐
                       │                    │                     │
                       ▼                    ▼                     ▼
              [HIM 原对比损失]      [Representation Loss]   [Intrinsic Reward]
              (与 next_obs 对齐)     (拉向 cmd 桶原型)        (塞回 PPO)
                                            │                     │
                                            └──────┬──────────────┘
                                                   ▼
                                           桶原型 e_b (共享)
```

**三组件**：
- **C1. 表征头（Representation Head）**：从 `obs_history` 编码出 `z_mode`，与可学习的"速度桶原型"对齐，提供监督式对比损失。
- **C2. 内在奖励发生器（Intrinsic Reward Generator）**：复用 C1 的对比 logit，将其作为标量内在奖励，注入策略优化路径。
- **C3. SMERL 门控（Gating）**：依据当前跟踪表现动态调节内在奖励权重，防止策略放弃跟踪去博取分化。

### 3.2 设计原则
1. **One network, two purposes**：同一份对比 logit 既驱动 representation learning，也驱动 policy gradient。避免引入额外的判别器网络与重复参数。
2. **Decoupled gradient paths**：表征损失只更新 encoder/原型；内在奖励经 detach 后只更新策略——**两条梯度通道物理隔离**，避免反馈放大。
3. **Curriculum on auxiliary signal**：内在奖励权重 α 以 warmup schedule 引入，避免早期对未成熟的 encoder 过度依赖。
4. **Gating by extrinsic performance**：内在奖励仅在外部跟踪 reward 达到阈值后开放，确保"先学会跟得上，再去分化"。
5. **Semantic separation of latents**：延续上一轮讨论结论——`z_dyn`（HIM 原"动力学响应"）与 `z_mode`（"步态模式"）使用独立 projection head，互不污染。

### 3.3 关键数学定义（设计层面）

为便于后续实现讨论，仅列出必要的符号：

- 历史观测 $o^h_t = (o^a_{t-H},\dots,o^a_t)$；
- 编码器输出 $z_{\text{mode},t} = \text{Norm}(g_\text{mode}(f(o^h_t)))$；
- 速度桶标签 $b_t \in \{1,\dots,K\}$，由 cmd 通过分桶函数得到；
- 桶原型 $\{e_b\}_{b=1}^{K}$，单位球上可学习向量。

**Representation 信号**（监督对比）：将 $z_{\text{mode}}$ 拉向其桶原型，推离他桶。

**Intrinsic reward 信号**：使用与 representation 相同的相似度结构，归一化并居中后作为标量塞入步级奖励。

**SMERL 门控**：跟踪奖励 EMA 与阈值 β 比较得到 gate ∈ [0,1]，与 α schedule 相乘后作为内在奖励权重。

## 4. 算法流程

### 4.1 系统级流程（每个 PPO iteration）

```
┌─ Phase 1: Rollout collection ───────────────────────────┐
│ for each env step:                                      │
│   1. 取 obs_history, cmd                                 │
│   2. encoder forward (no_grad) → z_dyn, z_mode, pred_v  │
│   3. actor 输入 = [obs_t, pred_v, z_dyn, z_mode]         │
│   4. 采样动作 a，step env，得到 r_track, r_aux, ...        │
│   5. 计算 cmd → bucket b                                 │
│   6. 计算 r_int = α(it)·gate(r_track_ema)·logit(z_mode,b)│
│   7. r_total = r_track + Σ w·r_aux + r_int               │
│   8. 写入 rollout buffer                                 │
└─────────────────────────────────────────────────────────┘

┌─ Phase 2: Compute returns / advantages ─────────────────┐
│   GAE(r_total) → A_t, R_t   (无任何特殊处理)              │
└─────────────────────────────────────────────────────────┘

┌─ Phase 3: Update ───────────────────────────────────────┐
│ for each minibatch:                                     │
│   3a. PPO 更新 actor / critic（使用 A_t）                  │
│   3b. encoder/原型更新：                                  │
│         L = L_vel + λ_dyn·L_dyn + λ_mode·L_proto         │
│             + λ_div·L_div                                │
│        （注意：obs detach；与 PPO 共享 batch 但独立 optimizer）│
└─────────────────────────────────────────────────────────┘

┌─ Phase 4: Schedule update ──────────────────────────────┐
│   α(it+1)，必要时调整 K（桶数 curriculum）                 │
└─────────────────────────────────────────────────────────┘
```

### 4.2 关键子流程

#### 子流程 A：速度桶映射（cmd → bucket）
**采用层次桶（Hierarchical Bucketing）**，与你 `unitree_rl_lab` 的"3-way mode isolation"约束对齐：

1. **粗类**（3 个）：`{standing, pure_wz, locomotion}`，由 cmd 各分量阈值判定。
2. **细类**：仅在 `locomotion` 内按 $\|v_{xy}\|$ 等距 / 分位数细分 $K_\text{fine}$ 桶。
3. 全局桶编号：`standing=0, pure_wz=1, locomotion_k = 2..2+K_fine-1`。

**理由**：
- 直接 3 维笛卡尔积 → 大量空桶 + 严重不均衡；
- 层次桶天然契合控制语义（站立 / 原地转向 / 行走是物理上不同的 mode）；
- 总桶数线性于细分数，可控。

#### 子流程 B：Representation 损失
- **主损**：原型 InfoNCE，把 $z_{\text{mode}}$ 拉向本桶原型；
- **辅助**：批级 SupCon（同桶为正），仅当 batch 内本桶正样本数 ≥ 2 时启用；
- **正则**：原型间多样性正则，防止原型坍缩到同一向量；
- **HIM 原信号保留**：`z_dyn` 仍按 HIM 原方法与 `next_obs` 对齐（独立 head + 独立原型集）。

#### 子流程 C：内在奖励计算
```
input:  z_mode_t (detached), bucket b_t, prototypes {e_b} (detached)
        r_track_ema (running average), schedule α(it), gate params β, κ
output: r_int_t (scalar)

steps:
  1. logits = (z_mode · proto.T) / τ
  2. log_p_b = log_softmax(logits)[b_t]
  3. r_raw = log_p_b + log K        # 居中到 ~0
  4. r_raw = clip(r_raw, [-c, c])   # 防异常值，c≈3
  5. gate = σ(κ · (r_track_ema - β))
  6. r_int = α(it) · gate · r_raw
```

#### 子流程 D：SMERL 门控更新
- 维护 `r_track_ema`，按 step 衰减更新（衰减因子 m ≈ 0.99）；
- 阈值 β 设定为 "策略勉强能跟上时" 的跟踪奖励水平（可由独立 baseline 跑一次估计，或取 r_track 历史 60% 分位数自适应）；
- κ 控制 gate 切换的陡峭程度，建议较大（≈10）使其接近软阈值但仍可微。

#### 子流程 E：Schedule 设计
| 量 | 推荐 schedule |
|---|---|
| α (内在奖励权重) | 0 → α_max（线性 warmup 至 30% iter，α_max ≈ 0.05~0.2） |
| τ (温度) | 固定 0.1，或从 0.2 退火到 0.07 |
| K_fine (细桶数) | 初期 4 → 后期 8~16（curriculum） |
| 桶原型学习率 | 与 encoder 同 lr 即可，初始化为高斯小方差 |

## 5. 需要注意的事项

### 5.1 安全性与正确性
1. **梯度隔离强制检查**：
   - 计算 `r_int` 时，z_mode 与 proto **必须 detach**；否则 PPO 会通过 reward 的反传修改 encoder，产生 reward hacking 反馈环（策略学会"伪造好被识别的 z"，而真实步态没有变化）。
   - 在代码 review 中应强制添加 unit test：检查 r_int 不携带 grad_fn。
2. **判别器/原型不能领先太多也不能落后太多**：
   - 若 encoder 还没学好就给大 α，r_int 噪声大、policy 被随机推；
   - 若 encoder 已收敛但 α 仍为 0，则相当于纯 representation，回到原问题。
   - **应通过 warmup 与 gate 双重保险**。
3. **r_int 范围控制**：`log p` 在 p→0 时趋向 −∞，必须 clip 防止单步奖励爆炸破坏 GAE。

### 5.2 训练稳定性
4. **桶不平衡**：on-policy 数据中高速桶天然样本少，可能导致：
   - 高速桶原型漂移；
   - 高速桶上的 r_int 估计方差大。
   - 对策：(a) 在 cmd resample 时人为提升稀有桶概率；(b) 给 representation loss 做 per-bucket 加权；(c) 引入 momentum encoder + queue（仅用于 representation，不用于 reward 计算，避免引入延迟偏差到 reward 中）。
5. **早期 cmd ≠ actual 偏差**：标签语义可能脏（前一轮讨论的问题）。
   - 对策：仅当 `‖cmd − EMA(actual)‖ < tol` 时该样本参与 representation 损失；该 gating 不影响 r_int 的发放（因为 r_int 评估的是"我现在执行的步态像不像桶 b 应有的样子"，cmd 与 actual 偏差大本身就该被低 r_int 惩罚）。
6. **Critic 必须能感知 r_int**：value head 输入应包含足够上下文（包含 cmd / z_mode），否则 critic 估计 r_int 的 advantage 方差会极大。
   - 在 manager_based_rl_env 中确认 critic obs 已包含 cmd（通常默认就有）。

### 5.3 防 Reward Hacking
7. **重点风险场景**：
   - 策略让机器人产生奇异姿态使 z_mode 异常大 → 错误地匹配某原型；
   - 原型与 encoder 一起漂移到无意义解，但 logit 数值上仍很高。
   - 对策：(a) z_mode 与原型均 L2 归一化 → logit ∈ [−1/τ, 1/τ] 有界；(b) 原型多样性正则 L_div 强制原型彼此远离；(c) 每隔 N iter 监控 "随机扰动 cmd 后 r_int 的变化"——若不敏感则说明 encoder 已坍缩，触发重新训练或 reset 原型。
8. **跟踪奖励权重不能压得太低**：r_track 必须仍是主导信号，r_int 只是"调味料"。建议保持 r_int 占 r_total 的稳态贡献 ≤ 15%。

### 5.4 与现有系统的兼容性
9. **与 HIM 的并存**：`z_dyn`（HIM 原信号）与 `z_mode`（新信号）共享 backbone、独立 projection head、独立原型集。两者损失加权相加，不要共用原型。
10. **IsaacLab 集成位置**：
    - 内在奖励应作为 `RewardManager` 中的一个新 `RewardTerm` 注册，便于 logging 与消融；
    - α schedule、β、κ 通过 cfg 暴露，避免硬编码；
    - encoder 与原型作为 actor-critic 的子模块，由 PPO runner 的 update 阶段同步训练（与 HIM Runner 一致）。
11. **部署一致性**：内在奖励仅在训练时生效；推理时 encoder 仍然提供 z_mode 给 actor，但不再计算 r_int。需要确保 inference 路径不依赖 r_int 相关的统计量。

### 5.5 评估与监控
12. **必备 logging 指标**：
    - `r_int_mean / std`、`gate_mean`（每 iter）；
    - `bucket_purity`：以 z_mode 在 batch 上跑 KMeans/最近原型，与真实 cmd 桶的一致性（NMI/ARI）；
    - `cross_bucket_action_distance`：固定 obs，遍历所有桶 cmd，测量 actor 输出动作分布的两两距离——这是"步态分化是否真的发生"的最终指标；
    - `r_track`、`tracking_error`：保证不退化。
13. **必备消融实验**：
    - A: 只 representation loss（无 r_int）→ 复现"知道但不动"问题；
    - B: 只 r_int（无 representation loss）→ 验证 r_int 是否单独足够；
    - C: 全方案 → 期望最佳；
    - D: 全方案 + 关闭 SMERL gate → 验证 gate 必要性。
14. **可视化**：
    - z_mode 的 t-SNE/UMAP 按桶上色（应清晰分簇）；
    - 不同桶下的足端接触序列时序图（步态差异的直观证据）；
    - r_int / gate / α 的 iteration 曲线。

### 5.6 失败模式与对策清单
| 现象 | 可能原因 | 优先排查 |
|---|---|---|
| 跟踪 reward 下降 | r_int 权重过大、gate 阈值过低 | 降 α_max、抬 β |
| z_mode 分簇但步态无差异 | reward hacking / encoder 坍缩 | 检查梯度隔离、检查 L_div、做 cross_bucket_action_distance |
| 高速桶完全不分化 | 高速桶样本太少 | 调高高速 cmd 采样概率、加 momentum queue |
| r_int 剧烈震荡 | logit 未 clip / τ 过小 | clip + 调大 τ |
| 训练后期所有桶又混到一起 | 原型漂移 / α schedule 退化 | 固定 α_max、监控原型间距离 |

## 6. 风险评估与回滚策略

### 6.1 主要风险
- **R1（高）**：reward hacking 导致跟踪性能退化但 metric 看起来很好。**缓解**：cross_bucket_action_distance 与 r_track 双指标必须同时改善才能视为成功。
- **R2（中）**：内在奖励引入后 PPO 训练方差显著上升。**缓解**：α warmup + gate + r_int clip 三重保护；必要时为 r_int 单独维护一个 value head。
- **R3（中）**：层次桶设定与实际任务分布不匹配。**缓解**：桶定义放在 cfg，通过短期实验快速迭代。
- **R4（低）**：encoder/原型与 PPO 同步训练带来时序耦合。**缓解**：encoder 优化器与 PPO 优化器分离；可以为 encoder 设置较小 lr。

### 6.2 回滚策略
本算法以"加法"方式接入：
- **关闭 r_int**（α=0）→ 回到纯表征学习（HIM-like 行为）；
- **再关闭 representation head**（λ_mode=0）→ 回到原始 PPO + HIM；
- **再关闭 HIM**（λ_dyn=0）→ 回到 vanilla PPO。

任何一层失败都可以无损降级，不破坏既有训练流程。

## 7. 后续可扩展方向（非本次必做）
1. **Soft / Ordinal 桶**：用 `Rank-N-Contrast` 形式让相邻速度桶在 latent 与 reward 上都有平滑过渡，避免速度变化时的步态突变。
2. **DADS 风格的 transition-level 内在奖励**：把 `q(s_{t+1}|s_t, b)` 的对数密度作为 reward，对地形扰动更鲁棒（计算成本更高）。
3. **多机器人共享原型**：在 cross-embodiment 训练时，桶原型作为统一的"步态语义锚"。
4. **与 H-Infinity Locomotion 的耦合**：将 z_mode 同时供给鲁棒控制器分支，验证步态分化是否提升抗扰性。

---

## 8. 总结

本算法通过将 **同一份监督对比 logit 同时用作"表征学习损失"与"策略内在奖励"**，并以 **SMERL 门控** 防止干扰跟踪任务，实现了在**完全无步态先验**条件下、按速度桶**自发演化**不同步态的目标。其本质是补上了"表征 → 策略"之间的梯度通道，让"行为可分性"成为策略本身的优化方向，而非仅仅是 encoder 的副产品。

设计在结构上保持模块化、可插拔、可消融，与现有 PPO + HIM + IsaacLab 框架完全兼容，并提供了从全方案到 vanilla PPO 的逐级回滚路径，便于实验与生产环境中的安全采用。
